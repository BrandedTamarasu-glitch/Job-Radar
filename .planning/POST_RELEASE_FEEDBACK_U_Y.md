# Post-Release Feedback Loop: Product Iteration U-Y

Created: 2026-05-15

## Goal

Collect useful post-release feedback without exposing private local job-search data. Feedback should help steer the next product iteration toward usability, coverage, performance, and release-trust improvements.

## Safe Feedback Fields

Users can share:

- App version and operating system.
- Which workflow they were using: dashboard, search setup, search results, applications, settings, updater, or release installer.
- Whether the issue affected setup, source selection, search quality, performance, review workflow, application tracking, or update/install flow.
- A short description of expected behavior and actual behavior.
- Validation detail that does not include private data, such as "search returned zero jobs" or "source diagnostics showed RemoteOK as low-yield."
- Screenshot only after redacting names, companies, saved searches, profile details, application notes, API keys, and local paths.

Users should not share:

- API keys, tokens, environment files, or GitHub credentials.
- Resume/profile contents, saved search names, target companies, application notes, or tracker history.
- Raw app-data bundles unless explicitly requested and reviewed for privacy.
- Local filesystem paths that reveal usernames or private project structure.

## Next Iteration Inputs

Track feedback into these buckets:

- Onboarding friction: anything that blocks first successful search.
- Search strategy: confusing presets, source recommendations, filters, or zero-result recovery.
- Result trust: scoring surprises, duplicate results, stale listings, or unclear match explanations.
- Workflow speed: review state, application follow-ups, saved searches, and repeated actions.
- Performance and stability: slow searches, cancellation, cache behavior, GUI freezes, build/update/install failures.
- Release trust: artifact download, checksum verification, auto-update, installer behavior, and version display.
