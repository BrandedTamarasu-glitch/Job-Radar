1. Add a richness scoring helper in `deduplication.py`:
   ```python
   def _job_data_richness(job) -> int:
       """Score how much useful data a job listing has.

       Higher score = more data. Used to pick the better listing when
       duplicates are found across sources.
       """
       score = 0
       if job.salary and job.salary not in ("Not listed", "Not specified", ""):
           score += 3  # Salary is high value
       if job.description and len(job.description) > 50:
           score += 2  # Meaningful description
       if job.salary_min is not None:
           score += 1  # Structured salary data
       if job.employment_type:
           score += 1
       if job.apply_info:
           score += 1
       if job.date_posted and job.date_posted not in ("Unknown", "Recent", ""):
           score += 1
       return score
   ```

2. Modify the duplicate handling in `deduplicate_cross_source()`:
   - In the exact duplicate branch (where `key in seen_keys`): compare richness of current job vs the seen job. If current job is richer, replace the seen job in the `seen` list.
   - In the fuzzy duplicate branch: same logic -- if the new job has higher richness score, swap it into the `seen` list replacing the less-rich duplicate.
   - When replacing, update `seen_keys` appropriately since the key might differ slightly.

   The replacement logic should be:
   ```python
   # In exact duplicate check:
   if key in seen_keys:
       # Find the existing job and compare richness

           existing_key = (seen_job.title.lower(), seen_job.company.lower(), seen_job.location.lower())
           if existing_key == key:
               if _job_data_richness(job) > _job_data_richness(seen_job):
                   seen[i] = job  # Replace with richer listing
                   log.debug("Replaced %s (%s) with richer listing from %s",
                            job.title, seen_job.source, job.source)
               break
       # ... (multi_source tracking stays the same)
       continue
   ```
