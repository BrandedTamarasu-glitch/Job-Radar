  <files>job_radar/gui/main_window.py</files>
  <action>
Integrate the full download flow into MainWindow: confirmation dialog -> asset fetch -> DownloadWorker start -> queue message routing -> banner state updates -> cancel/retry handling.

**Add imports:**
- `from job_radar.gui.worker_thread import create_download_worker` (add to existing import from worker_thread)
- `from job_radar.gui.update_banner import DownloadConfirmDialog` (add to existing import)

**Add instance variables in __init__:**
- self._download_worker = None
- self._download_thread = None
- self._update_tag = None  # GitHub tag for fetching assets
- self._download_cancelled_this_session = False  # Session-only suppress flag

**Modify _show_update_banner:**
- Pass on_download=self._on_download_requested to UpdateBanner constructor
- After creating banner, call self._update_banner.set_cancel_callback(self._on_download_cancel)
- Check self._download_cancelled_this_session — if True, don't show banner (session suppress per user decision: cancel dismisses until next program start)

**Add _on_download_requested(self, version: str):**
1. Fetch assets in background thread to avoid blocking UI:
   - Create thread that calls self._update_checker.fetch_release_assets(f"v{version}") (use self._update_tag if available, with "v" prefix)
   - After fetching, select platform asset via self._update_checker.select_platform_asset(assets)
   - If no matching asset: put ("download_failed", "No installer found for your platform") on self._queue, return
   - Otherwise: show DownloadConfirmDialog with version and asset['size']
   - On confirm: call self._start_download(asset, version)

   Implementation detail: Since fetch_release_assets does a network call, run it in a thread. Put result on queue as ("asset_ready", asset_dict, version) or ("asset_failed", error). Handle these new message types in _check_queue.

2. When DownloadConfirmDialog confirm callback fires (from "asset_ready" handler):
   - Call self._start_download(asset, version)

**Add _start_download(self, asset: dict, version: str):**
1. Get dest_path from self._update_checker.get_installer_download_path(version)
2. Transform banner to progress state: self._update_banner.show_progress()
3. Create download worker: worker, thread = create_download_worker(self._queue, asset['browser_download_url'], asset.get('digest'), str(dest_path))
4. Store self._download_worker = worker, self._download_thread = thread
5. Start thread: thread.start()

**Add _on_download_cancel(self):**
1. If self._download_worker: call self._download_worker.cancel()
2. Set self._download_cancelled_this_session = True
3. Destroy banner: self._update_banner.destroy(), self._update_banner = None

**Extend _check_queue with new message types:**

Add handlers for these message types (add elif branches in the existing message processing loop):

- "download_progress": unpack (_, downloaded, total). If self._update_banner: call self._update_banner.update_progress(downloaded, total).

- "download_complete": unpack (_, dest_path). If self._update_banner: call self._update_banner.show_complete(dest_path). Set self._download_worker = None, self._download_thread = None.

- "download_failed": unpack (_, error). If self._update_banner: call self._update_banner.show_failure(error). Set self._download_worker = None, self._download_thread = None.

- "download_cancelled": If self._update_banner: destroy banner, set to None. Set self._download_worker = None, self._download_thread = None.

- "asset_ready": unpack (_, asset, version). Show DownloadConfirmDialog(self, version, asset['size'], on_confirm=lambda: self._start_download(asset, version)).

- "asset_failed": unpack (_, error). If self._update_banner: call self._update_banner.show_failure(error).

**Update existing "update_available" handler:**
- Already updated in Plan 01 to unpack tag_name. Store self._update_tag = tag_name.

**Cleanup on app exit:**
- Override destroy() or use protocol("WM_DELETE_WINDOW") to cancel any active download worker before closing. If self._download_worker: self._download_worker.cancel(). This prevents orphaned threads downloading in background after app closes. The daemon=True on the thread handles ultimate cleanup, but cooperative cancel is cleaner.

**Important notes:**
- Do NOT block the main thread at any point. All network calls (asset fetch, download) happen in background threads.
- The existing _check_queue already runs on 100ms interval via self.after(100, self._check_queue) — no changes needed to polling frequency.
- Session suppress (self._download_cancelled_this_session) is an in-memory flag only — no config persistence needed (per user decision: cancel dismisses until next program start).
