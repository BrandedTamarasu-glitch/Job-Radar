<feature>
  <name>UpdateChecker: Version detection, throttling, and suppress tracking</name>
  <files>job_radar/update_checker.py, tests/test_update_checker.py</files>
  <behavior>
    Version comparison:
      is_newer_version("2.1.0", "2.2.0") -> True
      is_newer_version("2.9.0", "2.10.0") -> True (NOT string sort)
      is_newer_version("2.1.0", "2.1.0") -> False (same version)
      is_newer_version("2.2.0", "2.1.0") -> False (older)
      is_newer_version("2.1.0", "2.1.0-rc1") -> False (pre-release is older)
      is_newer_version("invalid", "2.1.0") -> False (graceful on bad input)

    Check throttling (should_check):
      No last_check in config -> True (first run)
      last_check 25 hours ago -> True (elapsed)
      last_check 2 hours ago -> False (too recent)
      auto_check_enabled=False -> False (user disabled)

    Suppress tracking (should_show_banner):
      Version not in suppressed -> True (show it)
      Version suppressed, expiry in future -> False (still suppressed)
      Version suppressed, expiry in past -> True (suppress expired)
      Different version suppressed -> True (per-version tracking)

    Dismiss behavior:
      dismiss_version("2.3.0", hours=24) -> saves expiry timestamp for that version
      dismiss_version("2.3.0", hours=168) -> saves 7-day expiry for that version

    GitHub API check (check_for_updates):
      Success with newer version -> queue message ("update_available", version, url)
      Success with same/older version -> queue message ("up_to_date",)
      Network timeout/error -> queue message ("check_failed", error_string)
      Saves last_check timestamp and check_success status on any outcome

    Config persistence:
      All state stored under "update_state" key in config.json at get_data_dir()
      Uses atomic write pattern (tempfile + rename) from profile_manager.py
      Keys: last_check (ISO timestamp), check_success (bool), suppressed_versions (dict), auto_check_enabled (bool)
  </behavior>
  <implementation>
    Create `job_radar/update_checker.py` with class UpdateChecker:
    - __init__(self, result_queue: queue.Queue | None = None): Accept optional queue for async results. Store config_path from get_data_dir() / "config.json".
    - is_newer_version(current: str, latest: str) -> bool: Static/classmethod using packaging.version.Version. Handle InvalidVersion gracefully (return False).
    - should_check(self) -> bool: Load config, check last_check timestamp against 24h threshold. Also check auto_check_enabled flag (default True).
    - should_show_banner(self, version: str) -> bool: Check suppressed_versions dict for version, compare expiry to now.
    - dismiss_version(self, version: str, hours: int) -> None: Save version with expiry timestamp to suppressed_versions in config.
    - check_for_updates(self) -> None: Call GitHub Releases API (https://api.github.com/repos/coryebert/Job-Radar/releases/latest) with User-Agent header, 10s timeout. Parse tag_name, html_url. Compare with __version__. Put result tuple on queue. Save check status.
    - get_update_status(self) -> dict: Return current status dict (last_check, check_success, auto_check_enabled) for Settings display.
    - set_auto_check(self, enabled: bool) -> None: Toggle auto_check_enabled in config.

    Config structure in config.json:
    {
      "update_state": {
        "last_check": "2026-02-16T10:30:00",
        "check_success": true,
        "auto_check_enabled": true,
        "suppressed_versions": {
          "2.3.0": "2026-02-23T10:30:00"
        }
      }
    }

    Use _write_json_atomic pattern from profile_manager.py (tempfile.mkstemp + os.replace).
    Use requests library (already a dependency) for GitHub API call.
    Use packaging.version.Version for comparison (stdlib, PEP 440 compliant).
    Import __version__ from job_radar for current version.

    Tests should mock:
    - datetime.now() for timestamp tests (use freezegun or manual patching)
    - requests.get for GitHub API tests
    - Config file reads/writes (use tmp_path fixture)
  </implementation>
</feature>
