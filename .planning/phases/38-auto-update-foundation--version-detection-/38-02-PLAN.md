    - Full-width banner with blue/teal accent color: fg_color=("#3498DB", "#2874A6") for light/dark mode, corner_radius=0

    - Download button: text="Download", width=100, calls webbrowser.open(release_url) to open GitHub Releases page in browser
    - Remind Later button: text="Remind Later", width=100, transparent bg with 1px border, calls on_remind(version) callback
    - X button: text="x" (plain x character, not emoji), width=30, calls on_dismiss(version) callback
    - All buttons in a single row, right-aligned with appropriate padding

    **Modify `job_radar/gui/main_window.py`:**

    1. Add imports at top: `from job_radar.update_checker import UpdateChecker` and `from job_radar.gui.update_banner import UpdateBanner`

    2. Modify grid layout in __init__: Change from 2-row (header, content) to 3-row layout:
       - row 0 = header (weight=0, fixed)
       - row 1 = banner (weight=0, fixed, initially empty)
       - row 2 = content (weight=1, expands)
       Update the _tabview grid call in _show_main_tabs to use row=2 instead of row=1.
       Update _show_welcome_screen content_frame placement to account for row shift.

    3. Add update checker state in __init__:
       - self._update_banner = None
       - self._update_checker = UpdateChecker(self._queue)
       - self._manual_check_button = None
       - self._update_status_label = None
       - self._manual_check_pending = False

    4. Add _start_update_check method (call after _show_main_tabs in __init__):
       - Only run if profile exists (no check on welcome screen)
       - Call self._update_checker.should_check() -- if False, return early
       - Start daemon thread calling self._update_checker.check_for_updates()

    5. Extend _check_queue to handle new message types:
       - "update_available": (_, version, release_url) -> call _show_update_banner if should_show_banner returns True. If _manual_check_pending, also update button text and status label.
       - "up_to_date": If _manual_check_pending, update button text to "Up to date!" and refresh status label. Otherwise no-op.
       - "check_failed": (_, error) -> store error for Settings display. If _manual_check_pending, update button text to "Check failed".

    6. Add _show_update_banner(self, version, release_url):
       - Destroy existing banner if any
       - Create UpdateBanner at row=1, column=0, sticky="ew"
       - Pass on_dismiss=lambda v: self._dismiss_update(v, 24) and on_remind=lambda v: self._dismiss_update(v, 168)

    7. Add _dismiss_update(self, version, hours):
       - Call self._update_checker.dismiss_version(version, hours)
       - Destroy self._update_banner, set to None

    IMPORTANT: Do NOT modify the existing _check_queue message handling for search worker messages. Add the new update message types alongside the existing ones using elif branches.

<task type="auto">
  <name>Task 2: Add Updates section to Settings tab</name>
  <files>job_radar/gui/main_window.py</files>
  <action>
    Add a dedicated "Updates" section to the Settings tab in _build_settings_tab, placed BEFORE the existing "API Key Settings" section (updates are more important than API keys).

    **Updates section content:**

    1. Section title: "Updates" (font size 18, bold) -- matches existing "API Key Settings" title style

    2. Status info line showing current version + last check + status:
       - Call self._update_checker.get_update_status() to get {last_check, check_success, auto_check_enabled}
       - Format: "v{__version__} -- Last checked: {relative_time} -- {status}"
       - relative_time: "Just now", "2h ago", "1d ago", "Never" (compute from last_check ISO timestamp)
       - status: "Up to date" (green), "Update available" (blue), "Check failed" (orange/yellow), "Never checked" (gray)
       - Store reference as self._update_status_label for refresh

    3. "Check for Updates" button with inline feedback:
       - Default text: "Check for Updates"
       - On click: disable button, change text to "Checking...", set self._manual_check_pending = True, start background thread with self._update_checker.check_for_updates()
       - On result (handled in _check_queue via _manual_check_pending flag):
         - up_to_date: change button text to "Up to date!" (re-enable), reset to default after 3 seconds via self.after(3000, ...)
         - update_available: change button text to "Update available!" (re-enable), show banner, reset after 3 seconds
         - check_failed: change button text to "Check failed" (re-enable), reset after 3 seconds
       - Also refresh the status info line after any result
       - Store button reference as self._manual_check_button

    4. "Check for updates automatically" toggle (CTkSwitch):
       - Read initial state from self._update_checker.get_update_status()["auto_check_enabled"] (default True)
       - On toggle: call self._update_checker.set_auto_check(enabled=bool)
       - Label: "Check for updates automatically on launch"

    5. Visual separator (CTkFrame with height=1, fg_color="gray") between Updates section and API Key Settings section

    **Queue message handling for manual check:**
    The _manual_check_pending flag (initialized in Task 1) distinguishes launch-time vs manual checks.
    In _check_queue, when processing update results and _manual_check_pending is True:
    - Update the button text and status label in Settings, then reset flag to False
    - Also reset button text after 3 seconds using self.after(3000, ...)
    When _manual_check_pending is False: only handle banner display (launch-time check behavior)

    Guard all Settings widget updates with `if self._manual_check_button is not None` since Settings tab is lazily built.
